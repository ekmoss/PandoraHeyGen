# Streaming Audio Processing Implementation Plan

## Overview

This plan outlines a strategy to implement streaming audio processing to reduce the recording latency identified as our primary bottleneck. Since WebSockets cannot be used due to VPN restrictions, we'll implement an HTTP-based chunked processing approach.

## Updated Performance Analysis

Recent performance metrics indicate the following key bottlenecks:
- **Audio processing time**: 49.3% of total latency (5600.30ms) is spent in "Process Final Chunk"
- **Audio size inefficiency**: Metrics show 14356.00ms for "audioSize", indicating potential format inefficiency
- **Azure API call**: 1788.69ms is spent in the actual API call to Azure

These metrics show that our primary optimization targets should be:
1. Audio format efficiency for faster processing
2. Transcription API latency improvement
3. Parallel processing opportunities

## Latest Test Results (After Initial Optimizations)

Recent tests show significant improvement but still require further optimization:
- **Audio processing time**: Reduced to 2959.60ms (47% faster)
- **Azure API call**: Reduced to 1651.89ms (8% faster)
- **End-to-end latency**: Reduced to 7103.90ms (37% faster)
- **Audio size**: Reduced to 6132 bytes (using audio/webm;codecs=opus)

## Phase II Optimization Targets

Based on test results and audio processing research, we need to focus on:

1. **Further Azure API Optimization**: The API call (1651.89ms) is now our primary bottleneck
2. **Audio Compression Improvement**: Further reduce audio size while maintaining speech quality
3. **Parallel Processing Implementation**: Split tasks to run concurrently

## Architecture

We'll adopt a progressive chunking strategy with these components:

1. **Client-side Audio Chunking**: Split audio into small chunks during recording
2. **Audio Format Optimization**: Use formats optimized for transcription speed
3. **Chunk-based Processing Pipeline**: Process each chunk as it becomes available
4. **HTTP-based Data Transfer**: Use efficient HTTP patterns for real-time processing
5. **Progressive Response Assembly**: Build the final response incrementally
6. **Parallel Processing Pipeline**: Process independent tasks concurrently

  const apiFormData = new FormData();

  // Select the appropriate optimization profile

### 4. Parallel Processing Implementation (NEW)

```javascript
// Process audio and handle results in parallel
async function parallelProcessAudioChunk(audioBlob, sessionInfo, isLastChunk) {
  const startTime = performance.now();
  
  try {
    // Create optimized audio in parallel with API prefetching
    const [optimizedAudio, _] = await Promise.all([
      compressAudioForProcessing(audioBlob, isLastChunk ? 'balanced' : 'ultraFast'),
      // Prefetch API connection in parallel
      fetch("/api/transcribe-chunk", { method: "HEAD" }).catch(() => {})
    ]);
    
    // Create form data
    const formData = prepareChunkFormData(
      optimizedAudio,
      sessionInfo.sessionId,
      sessionInfo.chunkSequence,
      isLastChunk
    );
    
    // Set appropriate timeout
    const timeoutMs = isLastChunk ? 8000 : 2000;
    
    // Process the API call
    const response = await fetch("/api/transcribe-chunk", {
      method: "POST",
      body: formData,
      signal: AbortSignal.timeout(timeoutMs),
      headers: {
        "Cache-Control": "no-cache",
        "Pragma": "no-cache",
        "Connection": "keep-alive",
      },
    });
    
    if (!response.ok) {
      throw new Error(`API error: ${response.status}`);
    }
    
    // Parse the response
    const result = await response.json();
    
    // If this is the final chunk and has text, start AI processing immediately
    // without waiting for UI updates
    if (isLastChunk && result.text && result.text.length > 0) {
      // Process with AI in parallel - don't await
      processWithAI(result.text);
    }
    
    return {
      ...result,
      metrics: {
        ...result.metrics,
        clientProcessingTime: performance.now() - startTime
      }
    };
  } catch (error) {
    console.error("Error in parallel processing:", error);
    return {
      text: "",
      combinedText: "",
      isPartial: !isLastChunk,
      error: error instanceof Error ? error.message : "Unknown error",
      chunkSequence: sessionInfo.chunkSequence,
      sessionId: sessionInfo.sessionId,
      metrics: {
        clientProcessingTime: performance.now() - startTime
      }
    };
  }
}
```

### 5. Server-Side Caching and Optimization (NEW)

```typescript
// Add advanced caching on the server side
// Cache both the audio processing results and the AI responses
const audioProcessingCache = new Map<string, {
  result: any;
  timestamp: number;
  audioHash: string;
}>();

// Generate a hash for audio content to identify similar audio
function generateAudioHash(audioSize: number, firstBytes: Uint8Array): string {
  // Create a simple hash based on audio size and first few bytes
  // This allows us to identify similar audio segments
  const bytesSignature = Array.from(firstBytes.slice(0, 8))
    .map(b => b.toString(16).padStart(2, '0'))
    .join('');
  
  return `${audioSize}-${bytesSignature}`;
}

// Advanced caching with audio similarity detection
async function getCachedTranscription(
  audioBlob: Blob, 
  sessionId: string, 
  chunkSequence: number
): Promise<any | null> {
  // Get the first few bytes of the audio to create a signature
  const arrayBuffer = await audioBlob.arrayBuffer();
  const firstBytes = new Uint8Array(arrayBuffer.slice(0, 16));
  
  // Generate audio hash
  const audioHash = generateAudioHash(audioBlob.size, firstBytes);
  
  // Check exact match first
  const cacheKey = `${sessionId}:${chunkSequence}:${audioBlob.size}:${audioBlob.type}`;
  const exactMatch = audioProcessingCache.get(cacheKey);
  
  if (exactMatch) {
    return {
      ...exactMatch.result,
      fromCache: true,
      cacheType: 'exact'
    };
  }
  
  // Check for similar audio
  for (const [key, value] of audioProcessingCache.entries()) {
    // If the audio hash is similar and not too old (within 10 minutes)
    if (value.audioHash === audioHash && 
        Date.now() - value.timestamp < 10 * 60 * 1000) {
      return {
        ...value.result,
        fromCache: true,
        cacheType: 'similar'
      };
    }
  }
  
  return null;
}
```
