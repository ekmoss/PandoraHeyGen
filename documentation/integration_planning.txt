## Critical Architecture Learnings

### Next.js 13+ Component Architecture
1. Server-First Principles:
   - Pages should be server components by default
   - Only use "use client" for components that truly need browser APIs
   - Use dynamic imports with { ssr: false } for client components
   - Keep pages as server components and dynamically import interactive components

2. Common Pitfalls to Avoid:
   - Don't add "use client" to page components
   - Don't try to fix hydration issues by making everything client-side
   - Don't mix server and client state in the same component

3. Debugging Process for Hydration Issues:
   1. Check component architecture first
   2. Look for client/server component mismatches
   3. Verify dynamic imports are properly configured
   4. Only then investigate specific errors

4. Best Practices:
   ```typescript
   // Good - Page as server component
   // app/page.tsx
   import dynamic from 'next/dynamic'
   
   const InteractiveComponent = dynamic(
     () => import('@/components/InteractiveComponent'),
     { ssr: false }
   )
   
   export default function Page() {
     return <InteractiveComponent />
   }
   
   // Bad - Don't do this
   // app/page.tsx
   'use client'
   import InteractiveComponent from '@/components/InteractiveComponent'
   ```

These learnings came from debugging hydration issues in our voice integration implementation. Following these principles helps prevent common issues and maintains better performance through proper server/client component separation.
